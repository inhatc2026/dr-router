# 채팅과 의료기관 목록 연결

담당: 박태준 · 기준: 요구사항정의서 v0.5, PR #4~#5의 공유 계약과 검색 기능

`chat.html`에서 입력한 증상과 이전 대화, 위치 또는 지역명을 `POST /api/chat`으로 보낸다. 응답의 문진 메시지·추천 진료과·응급 안내를 표시하고, `hospitals.html`에서 같은 응답의 의료기관 목록을 확인한다. 화면의 예시 병원·가용 병상·진단 확률은 제거했다.

## 응답 표시

| 필드 | 화면 동작 |
|---|---|
| `kind` | 병원·약국·응급실 필터. 종류 구분 없이 전체 거리순(FR-20). 응급 응답은 응급실만 표시 |
| `is_open` | `true`는 진료중, `false`는 진료중 아님, `null`은 **확인 필요**. 진료중 필터에는 `true`만 포함 |
| `address` | 카드와 선택한 지도에 주소 표시. 누락 시 주소 정보 없음 |
| `lat`, `lng` | 기관별 색상·글자 마커와 조회 당시 GPS 위치. 좌표가 없거나 유효하지 않으면 마커를 만들지 않고 지도 버튼 비활성화 |
| `distance_m` | 1 km 미만은 m, 그 이상은 km. 5 km를 넘는 결과도 그대로 표시하며 상한으로 자르지 않음 |
| `phone` | 유효한 번호만 `tel:` 링크. 누락 시 전화번호 정보 없음 |
| `dept` | 병원 응답의 이름 그대로 표시. 추천 소화기내과와 검색 결과 내과는 구분 |
| `er_beds`, `er_beds_at` | 응급실만, 실제 E-Gen 실시간 가용병상이 있을 때만 응답에 들어옴. `병상 N · HH:MM 기준`(초록), 0 이하는 `병상 포화`(빨강), 상세 정보에 "실제와 다를 수 있으니 전화 확인" 안내. 없으면 배지 없음(구버전 응답과 같음) |

지도는 Leaflet으로 필터에 맞는 기관의 마커와 조회 당시 GPS 위치를 함께 표시한다. 색상 외에도 병·약·응·나로 구분한다. 지도 타일은 OpenStreetMap 네트워크에 의존하며, 실패 시 안내·주소·거리·전화·큰 지도 링크를 유지한다. 지도 API 키는 필요 없다. GPS를 받지 못했을 때 지역의 임의 좌표를 내 위치로 표시하지 않는다.

Leaflet 1.9.4 JS/CSS와 라이선스는 `frontend/assets/vendor/leaflet/`에 고정해 포함했다. [공식 1.9.4 API 문서](https://leafletjs.com/reference-1.9.4.html) 기준이며 출처는 같은 폴더의 README를 참고한다. 외부 CDN에서 실행 코드를 매번 받지 않는다.

## 입력과 상태

- 빈 입력과 500자 초과 입력은 안내 후 전송하지 않는다. 입력 길이를 표시한다(FR-01, EX-01).
- 위치 요청은 ‘현재 위치 사용’ 버튼을 누를 때만 한다. 권한 거부·시간 초과 시 시·군·구/읍·면·동 입력으로 대신할 수 있다. `region`은 계약 그대로 전달하며 GPS가 있으면 함께 보내 후보 확인에 쓸 수 있게 한다. 지역명 우선 처리와 후보 제안은 PR #5의 검색 도구 및 그래프 연결 담당이다.
- 요청 중 중복 전송을 막고, 45초 지연·HTTP 실패·형식 오류를 안내한다. 실패한 입력은 유지하며 성공한 대화만 다음 요청의 `history`에 포함한다.
- `need_more_info`이면 추천 카드·결과 링크 없이 질문만 표시한다. 응급 플래그가 함께 오면 응급 안내가 우선이다(FR-03).
- 응급 응답은 채팅 안에서 119 전화 버튼과 가까운 응급실 최대 3곳을 표시한다. 응답에 일반 병원이 섞여도 제외한다. 목록이 없어도 안내는 유지한다. 다음 입력은 이력을 비운 새 문진으로 전송한다(FR-10, EX-09).
- 진료과 후보는 유효한 score 내림차순 최대 3개와 reason을 표시한다. 선택 필드 `sources`가 있으면 근거 문서명을 표시하고, 없으면 확인 필요와 상담 안내를 유지한다. 1순위가 0.5 미만이면 출처 유무와 관계없이 낮은 확신도 알린다. 점수는 진단 확률로 표현하지 않는다(FR-12~14). 분류 및 계약 변경은 [classification.md](classification.md)를 참고한다.
- 카드에는 상세 정보 펼치기와 전화 연결을 제공한다. 응답 화면에 참고용 안내를 유지한다(FR-22, NFR-01).
- 목록 이동에는 현재 탭의 `sessionStorage`를 사용한다. 의료기관 결과·후보과 이름·조회 시각·검색 지역 표시·조회 당시 GPS만 30분간 보관하고, 증상 원문·대화 이력·분류 근거는 저장하지 않는다. 새 전송이나 새 문진을 시작하면 이전 목록을 지운다. 서버에 저장하지 않는다.
- 대화 이력은 채팅 페이지 메모리에만 있다. 새로고침하거나 새로 페이지를 열면 대화는 초기화된다.
- 외부 응답 텍스트는 `textContent`로 표시해 HTML로 실행하지 않는다.

## 실행과 검증

프로젝트의 Python 의존성을 설치한 환경에서 저장소 루트에서 실행한다.

```powershell
python -m uvicorn backend.main:app --reload
```

`http://127.0.0.1:8000/chat.html`에서 문진을 시작한다. 기존 가상환경을 이용한다면 해당 환경의 Python으로 실행한다.

프론트 테스트는 Node.js 20 이상에서 실행한다. Playwright는 테스트 전용이며 서비스 화면에는 필요하지 않다.

```powershell
npm ci
npm run test:frontend
npx playwright install chromium
npm run test:browser
```

Windows에 Edge가 이미 설치돼 있으면 브라우저 다운로드 대신 다음처럼 실행할 수 있다.

```powershell
$env:PLAYWRIGHT_CHANNEL = 'msedge'
npm run test:browser
```

- 단위 검사: 상태 3종, 필터·정렬, 거리, 좌표, 전화 링크, 요청 계약·실패, 결과 만료.
- 브라우저 검사: 채팅 → 추가 문진 → 결과 목록, 위치 허용·거부, 필터, 장거리, 지도 좌표, 빈 목록, 응급 안내, 재시도, 텍스트 안전 처리, 모바일 레이아웃.
- 브라우저 검사는 자체 임시 정적 서버와 API·지도 응답 fixture를 사용하며 종료 시 서버와 브라우저를 닫는다. 캡처는 Git에서 제외되는 `test-results/`에 저장된다. 실제 공공 API나 외부 지도 타일의 가용성을 검증하는 테스트는 아니다.
- 2026-11-16 v0.5 보완 확인: 단위 테스트 8개와 브라우저 시나리오 통과. 500자 제한·빈 입력, 잘못 섞인 추가 질문 결과 숨김, 응급실 제한·새 문진, 점수 정렬·낮은 확신, 상세 펼치기, 마커 종류·GPS, 홈·문진·목록의 360px 레이아웃을 검사했다. 주요 글자색 대비 4.5:1, 보이는 본문 16px, 조작 요소 44px 이상도 확인했다. 전체 접근성 인증이나 스크린리더 검증을 뜻하지 않는다.
- 이전 연결 단계에서는 실제 FastAPI 스텁의 일반 입력·응급 입력·빈 목록을 확인했다. v0.5 변경의 브라우저 검사는 모의 API 응답이며 실제 병원 검색 완주를 검증한 것이 아니다.

## 통합 시 남은 사항

팀장 PR #6의 실제 그래프와 `fix/taejoon-graph-integration` 보완에 연결한다. `region` 전달, 응급실 검색, 지역 확인이 연결됐으며 분류/RAG 함수는 아직 스텁이다. 프론트 단독 브랜치의 구형 그래프가 아니라 세 변경이 합쳐진 버전으로 실행해야 한다. 공유 계약 필드는 변경하지 않았다.

클로드 검토에서 재현한 응급 조회 지연, 지역 확인 반복, 지역 DB 없음의 GPS 대체는 그래프 보완에서 수정했다. 프론트는 결과 머리말을 **요청 지역/요청 GPS**로 표시하며 실제 검색 중심점을 추측하지 않는다. 실패한 전송의 임시 말풍선을 제거해 재전송 때 중복되지 않는다.

세 변경을 합친 checkout에서 Python 122개 중 118개 통과·외부 API 4개 건너뜀, 프론트 단위 8개 및 브라우저 검사 통과를 확인했다. 실제 uvicorn + LangGraph + 합성 SQLite + 모바일 브라우저에서도 지역 확인 → 약국/응급실 목록, 치과 위험 문장 → 응급실 안내, 응급 후 새 문진을 통과했다. 임시 서버와 DB는 검사 종료 시 정리한다. 실제 공공 API 데이터나 분류 정확도를 검증한 것은 아니다.

```powershell
# 그래프 보완과 응급 규칙까지 합친 저장소에서, Python 가상환경 활성화 후
$env:PLAYWRIGHT_CHANNEL = 'msedge'
node eval/test_frontend_live.cjs
# 필요한 경우 $env:TEST_PYTHON에 가상환경 python.exe 경로 지정
```

| FR-03/04/05 | 질문 최대 2개, 연속 3회 제한과 증상 외 입력 처리(collect/그래프). 프론트가 임의로 분류를 만들지 않음 |

v0.5의 수치 목표·규칙 승인 주체는 회의 안건이며 확정된 정책으로 확대하지 않았다. 음성 입력(FR-27 선택)은 이번 보완 범위에서 구현하지 않았다. 그래프 보완 내역은 `docs/graph_integration_review.md`에 있다. 실제 공공 DB/API와 출처가 연결된 뒤 추가 통합 확인이 필요하다.
