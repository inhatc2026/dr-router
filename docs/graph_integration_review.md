# 그래프 통합 검토 보완

팀장 PR #6과 클로드 검토 결과를 반영한다. 공유 State/API 필드는 변경하지 않는다.

- 모든 입력은 START → triage로 시작한다. 응급이면 collect/분류/일반 검색을 건너뛰며, 지역 확인 때문에 응급 분기가 생략되지 않는다.
- 응급실 조회 응답 대기는 0.5초이다. 조회 작업이 늦거나 실패하면 빈 목록과 119 안내를 반환한다. 실행 중인 네트워크 호출 자체는 취소하지 못한다. 최대 2개 작업과 슬롯으로 동시 조회를 제한하고 포화 시 대기열 없이 빈 목록을 반환한다. 이는 응답 대기 예산이며 팀의 NFR-07 전체 성능 목표 검증을 뜻하지 않는다.
- 지역명은 GPS가 있어도 확인한다. 모호하면 GPS는 후보 정렬에만 사용한다. 바로 앞 질문에 대한 ‘네’, ‘네 인천 중구 맞아요’ 같은 명시적 답변을 history에서 확인하고, 실제 지역 DB의 ok 판정 후 진행한다. 이후 턴에도 확인된 지역을 복원한다. 앞서 입력한 증상은 분류 입력에 유지한다. 자유 형식의 모든 확인 표현을 이해하는 LLM 구현은 아니다.
- 지역 DB가 없거나 오류면 지역 검색 불가를 알리고 결과를 내지 않는다. GPS로 찾으려면 사용자가 지역 입력을 비우도록 안내한다. 입력 지역을 몰래 GPS로 대체하지 않는다.
- 분류 결과 없음은 재질문 대신 방문 상담 안내와 need_more_info=False로 정렬한다. 후보가 있어도 근거 출처 계약이 없으므로 확정 진단·확정 추천 문구를 쓰지 않는다.

`python -m unittest eval.test_graph_integration -v`는 실제 LangGraph와 FastAPI를 실행한다. 외부 서비스는 모의하되 지역 확인/재확인 검사는 임시 SQLite와 실제 resolve_region/search 코드를 거친다. 지연된 E-Gen 조회의 응답 마감과 대기열 제한, DB 없음, 지역 후보 거절, 다음 턴 확인 유지도 검사한다. `eval/graph_fixture.py`의 기관은 전부 합성 테스트 데이터다.

분류/RAG, 일반 증상 충분성 판단, 질문 횟수 제한은 여전히 스텁/후속 범위다. 실제 공공 API 데이터와 키 없이 외부 API의 정확성·가용성을 검증했다고 주장하지 않는다. 응급 경로에서 확인 지역과 실제 GPS 중 무엇을 우선할지는 팀 결정이 필요하며 기존 검색 정책은 유지한다.
